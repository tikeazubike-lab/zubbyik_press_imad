## 2. Correction to HO-032 §4b — a real limitation I should have caught first

HO-032 §4b said "add a second certresolver + second token" as if this
were a simple config addition. It isn't, and I should have verified this
before writing it rather than after: **Traefik's Cloudflare DNS-01
provider reads its credentials (`CF_DNS_API_TOKEN`) from the container's
process-wide environment, not from per-resolver configuration.** Two
`certificatesResolvers` entries both set to `dnsChallenge.provider:
cloudflare` in the same Traefik instance will both read the *same*
environment variable — there's no way to give the second resolver a
different Cloudflare token while both live in one process. This is a
known Traefik/lego limitation, not a config mistake on anyone's part.

**Do not implement HO-032 §4b as written.** Two real options instead:

### Option A — HTTP-01 for this one host (recommended)

Give `api.imadconsulting.co.uk` its own certresolver using the HTTP-01
challenge instead of DNS-01. HTTP-01 needs zero Cloudflare credentials —
it just requires Let's Encrypt's validator to reach Traefik on port 80 for
that hostname. This sidesteps the multi-account problem entirely rather
than working around it.

**Verify both of these before implementing — do not assume either:**
```bash
curl -I http://api.imadconsulting.co.uk    # from an EXTERNAL host, not the VPS itself
```
Expect a response from Traefik (even a redirect/404 is fine — anything
other than a timeout or connection refused). And check the Cloudflare
proxy status for that DNS record: dashboard → DNS → find the
`api.imadconsulting.co.uk` record → confirm whether the cloud icon is
orange (proxied) or grey (DNS only). Report both results before
proceeding — if port 80 isn't reachable or the record is proxied in a way
that interferes with the plain-HTTP validation request, this option needs
adjusting before it's attempted, not after a failed attempt burns another
authorization.

**If both check out**, add to `traefik.yml`:
```yaml
certificatesResolvers:
  letsencrypt-http:
    acme:
      email: <your existing ACME email>
      storage: /letsencrypt/acme-http.json   # separate storage file — do not share with the DNS-01 resolver's acme.json
      httpChallenge:
        entryPoint: web
```
Then change only the `imad-automation` router's label:
```yaml
- "traefik.http.routers.imad-automation.tls.certresolver=letsencrypt-http"
```
Everything else (the existing `letsencrypt` DNS-01 resolver used by
`zubbystudio.site` services) is untouched — this adds a second resolver
alongside the first, it doesn't replace it.

### Option B — separate Traefik instance for imadconsulting.co.uk's certs

Technically possible (a second Traefik container with its own env vars,
listening on different ports or fronted differently) but meaningfully
heavier for one hostname's certificate. Not recommended unless Option A's
verification fails for a reason that can't be fixed (e.g. port 80
genuinely unreachable and can't be opened).
