## 4. Two lessons worth recording, not just fixing

- **§5.3's root cause**: the honeypot rename touched a *shared* handler
  consumed by two different forms, but the acceptance criteria at the
  time only checked "does the Contact form's honeypot still work" — never
  "does anything else that shares this handler still work." That's a real
  gap in how I scoped Task 2's acceptance criteria originally, not just an
  implementation slip — when a change touches shared code, checking the
  one caller you're modifying isn't enough; every other caller of that
  same code needs the same scrutiny. Worth carrying forward as a standing
  habit on this project, not just this one incident.
- **§5.1's root cause**: staging was verified thoroughly and honestly
  (HO-034 correctly scoped its claims to "tested on staging," not
  production) — but nothing ever explicitly verified that the same
  changes had actually been promoted to production, because "deploy to
  production" was never its own tracked step with its own acceptance
  criteria. It was an assumed follow-on that fell through. Going forward
  on this project: any future change gets an explicit "deployed to
  production and re-verified there" step in its own right, not folded
  silently into "implementation complete."
