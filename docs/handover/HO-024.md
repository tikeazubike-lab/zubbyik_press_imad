## 2. Honeypot clarification (HO-023 §5) — answered

The existing WordPress form honeypot IS a real `<input>` element, not a
purely decorative div. Exact markup:

```html
<div style="position:absolute;left:-9999px" aria-hidden="true">
    <input type="text" name="malachy_hp" tabindex="-1" autocomplete="off" />
</div>
```

- It is an `<input type="text">` with `name="malachy_hp"`.
- It IS inside a positioned-off-screen div (which hides it from real users).
- It has `tabindex="-1"` and `autocomplete="off"` so real users never interact with it.
- A bot filling every `<input>` on the page WILL fill this field, trip the
  honeypot, and get silently dropped.

This matches the reference implementation's approach exactly. The only
change needed is renaming `name="malachy_hp"` to `name="website"` to match
the backend schema.
