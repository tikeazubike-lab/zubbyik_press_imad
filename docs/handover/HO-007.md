## 3. JS Error Response Handling

```javascript
// Called from sendMessage() after fetch to /wp-json/malachy/v1/chat
const data = await response.json();

// credit_exhausted / no_api_key → contact form fallback
if (data.code === 'credit_exhausted' || data.code === 'no_api_key') {
    this.showCreditFallback();
    return;
}

// rate_limited → descriptive message
if (data.code === 'rate_limited') {
    this.messages.push({
        role: 'assistant',
        content: "You've sent too many messages — please wait a moment before trying again.",
    });
    this.renderMessages();
    return;
}

// api_error → PHP's specific message (e.g. "Could not connect to AI service...")
if (data.code === 'api_error' && data.message) {
    this.messages.push({ role: 'assistant', content: data.message });
    this.renderMessages();
    return;
}

// !response.ok → fallback message with status code
if (!response.ok) {
    const errMsg = data.message || `Request failed (${response.status})`;
    this.messages.push({ role: 'assistant', content: errMsg });
    this.renderMessages();
    return;
}

// catch (network error) → generic apology with contact form prompt
} catch (err) {
    console.error('Chatbot API error:', err);
    this.messages.push({
        role: 'assistant',
        content: "Sorry, I couldn't process that request. Please try again or reach out via the contact form.",
    });
    this.renderMessages();
}
```

| `rate_limited` | "You've sent too many messages — please wait..." |
| `api_error` | PHP's specific `data.message` string |
| HTTP error | `data.message` or "Request failed ({status})" |
| Network exception | "Sorry, I couldn't process that request..." |
| Success | `data.reply` displayed normally |
