## 1. §3 — Telegram token removed from container logs: DONE and verified

### Change

`imad-automation/app/main.py`, immediately after `logging.basicConfig(...)`:

```python
# httpx logs the full request URL at INFO level. For Telegram calls that URL
# contains the bot token, so a live token would otherwise be written to the
# container log on every send (and from there into any log aggregation).
# Keep httpx at WARNING so tokens never reach the logs; our own imad.*
# loggers are unaffected.
logging.getLogger("httpx").setLevel(logging.WARNING)
logging.getLogger("httpcore").setLevel(logging.WARNING)
```

Committed `4f6fa23`. Container rebuilt and recreated.

### Verification (post-fix, with a real send)

```
$ docker exec imad-automation python -c "...POST /api/leads..."
insert: 200 {"status":"ok","lead_id":6}

$ docker exec -i openagile_postgres psql ... -tc "SELECT count(*) FROM leads;"
     6                       # lead stored

$ docker exec -i openagile_postgres psql ... -tc "SELECT count(*) FROM dead_letters;"
     4                       # UNCHANGED -> the Telegram send succeeded (no dead-letter)

$ docker logs imad-automation | grep -c "AAEcvD8t"      # the token string
0
$ docker logs imad-automation | grep -c "sendMessage"   # the request line
0
```

So: the notification still goes out (no new dead-letter, lead persisted), and the
token string now appears **zero times** across the entire container log. Only
uvicorn's own access line is left:

```
INFO:     127.0.0.1:40234 - "POST /api/leads HTTP/1.1" 200 OK
```

## 2. §2 — Dedicated bot: decision made, creation cannot be automated

Decision recorded: **Malachy wants a dedicated bot** for leads, separate from
`imadconsultingBot` (which the WordPress visitor chatbot uses), so a new lead
can't be lost in unrelated traffic.

**I can't create this for you.** Telegram has no API to create bots — only
@BotFather can, and it's an interactive chat with a human Telegram account.
There's no CLI/HTTP path. So this needs ~60 seconds in the Telegram app:

1. Open Telegram, message **@BotFather**.
2. Send `/newbot`.
3. Give it a name (e.g. `IMAD Leads`) and a username ending in `bot`
   (e.g. `imad_leads_bot`).
4. BotFather replies with a token like `123456789:AAE...`. **Send it to me.**
5. **Send any message to the new bot** (e.g. "hello") so it has a chat to
   deliver to.
6. Then I'll call `getUpdates` to read the new `chat_id`.

Once you paste the token (and confirm step 5), I will:

- set `IMAD_TELEGRAM_BOT_TOKEN` + `IMAD_TELEGRAM_CHAT_ID` in `.env` to the new
  bot,
- recreate the container,
- re-run the direct `sendMessage` + browser Test 3 to prove the new bot
  delivers (same evidence standard as HO-036 §4).

**Interim state:** lead notifications currently go to the shared bot's chat.
Nothing is broken while this is pending — the system works; it just doesn't
have the split you asked for yet.
